# volleyball_inline_bot

Telegram-бот записи на волейбол. На каждую игру бот публикует сообщение со списком игроков и кнопками записи, держит в закрепе доску со всеми ближайшими играми, а после игры собирает оплату зала. Решения и задачи описаны в [.docs/inline-signup-feature.md](.docs/inline-signup-feature.md).

## Требования

- Go 1.25 или новее.
- Супергруппа Telegram без тем (ID начинается с `-100`). Ссылки с доски на сообщения игр (`https://t.me/c/...`) работают только в супергруппах. Обычная группа становится супергруппой автоматически, например при включении видимости истории для новых участников.
- Бот добавлен в группу администратором с правами «Закрепление сообщений» и «Удаление сообщений». Без закрепления доска не попадёт в закреп, без удаления не будут удаляться старые игры.

## Настройка

1. Создать бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и получить токен.
2. Добавить бота в группу и назначить администратором с правами из раздела «Требования».
3. Узнать ID группы. Пока бот не запущен, отправить в группе `/start@<имя_бота>` и открыть в браузере:
   ```
   https://api.telegram.org/bot<токен>/getUpdates
   ```
   ID группы находится в поле `"chat":{"id":-100...}`. Пока бот запущен, этот запрос вернёт ошибку `Conflict`: апдейты в это время получает сам бот.
4. Создать `.env` по образцу:
   ```bash
   cp .env.example .env
   ```
   Заполнить `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Остальные переменные необязательны, их значения по умолчанию описаны в `.env.example`. Если `.env` нет, переменные читаются из окружения.

## Запуск

Из корня проекта:

```powershell
go run .
```

Сборка в исполняемый файл:

```powershell
go build -o bin\volleyball_inline_bot.exe .
.\bin\volleyball_inline_bot.exe
```

При ошибке в конфигурации бот пишет её в лог и завершается с кодом 1. Остановка через Ctrl+C: бот дожидается завершения текущих задач планировщика и выходит.

Тесты:

```powershell
go test ./...
```

## Файл данных

Игры, списки игроков, отметки оплаты, реквизиты плательщиков и ID доски хранятся в одном JSON-файле, путь задаёт `STORE_PATH` (по умолчанию `data.json` в рабочей папке). Запись атомарная: бот пишет во временный `data.json.tmp` и заменяет им основной файл, поэтому сбой во время записи не портит данные.

Если файл потерян, бот начинает с пустого состояния: создаёт новую доску и закрепляет её, а сообщения старых игр остаются в чате, но кнопки в них перестают работать. Их нужно удалить вручную. При запуске в Docker файл нужно держать в volume, иначе он пропадает вместе с контейнером.
