# volleyball_inline_bot

Telegram-бот записи на волейбол. На каждую игру бот публикует сообщение со списком игроков и кнопками записи, держит в закрепе доску со всеми ближайшими играми, а после игры собирает оплату зала. Решения и задачи описаны в [.docs/inline-signup-feature.md](.docs/inline-signup-feature.md).

## Требования

- Go 1.25 или новее.
- Супергруппа Telegram без тем (ID начинается с `-100`). Ссылки с доски на сообщения игр (`https://t.me/c/...`) работают только в супергруппах. Обычная группа становится супергруппой автоматически, например при включении видимости истории для новых участников.
- Бот добавлен в группу администратором с правами «Закрепление сообщений» и «Удаление сообщений». Без закрепления доска не попадёт в закреп, без удаления не будут удаляться старые игры.

## Настройка

1. Создать бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и получить токен.
2. Добавить бота в группу и назначить администратором с правами из раздела «Требования».
3. Узнать ID группы. Пока бот не запущен, отправить в группе `/start@<имя_бота>` и открыть в браузере:
   ```
   https://api.telegram.org/bot<токен>/getUpdates
   ```
   ID группы находится в поле `"chat":{"id":-100...}`. Пока бот запущен, этот запрос вернёт ошибку `Conflict`: апдейты в это время получает сам бот.
4. Создать `.env` по образцу:
   ```bash
   cp .env.example .env
   ```
   Заполнить `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Остальные переменные необязательны, они перечислены в разделе «Переменные окружения». Если `.env` нет, переменные читаются из окружения.

## Переменные окружения

Пустое или отсутствующее значение означает значение по умолчанию. Некорректное значение останавливает бот при старте с сообщением, какая переменная неверна. Расписания задаются в формате cron (минута, час, день, месяц, день недели) и считаются в `TIMEZONE`. Длительности задаются в формате Go: `90s`, `10m`, `1h`.

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | обязательна | Токен бота |
| `TELEGRAM_CHAT_ID` | обязательна | ID супергруппы |
| `STORE_PATH` | `data.json` | Путь к файлу данных |
| `TIMEZONE` | `Europe/Moscow` | Таймзона планировщика и дат |
| `GAME_DAYS` | `Tuesday,Thursday,Friday,Sunday` | Игровые дни, англ. названия через запятую |
| `GAME_TIME` | `19:00` | Время игры в сообщении, `ЧЧ:ММ` |
| `CRON_SCHEDULE` | `0 20 * * *` | Когда проверять, нужно ли создать игру |
| `CREATE_DAYS_AHEAD` | `7` | За сколько дней до игры создаётся её сообщение |
| `CLEANUP_SCHEDULE` | `0 6 * * *` | Когда переводить прошедшие игры в режим оплаты и удалять старые |
| `DELETE_AFTER_DAYS` | `14` | Через сколько дней после игры удаляются её сообщения |
| `BOARD_CHECK_SCHEDULE` | `0 * * * *` | Когда проверять доску и её закреп |
| `PLAYERS_LIMIT` | `12` | Сколько человек нужно на игру |
| `MAX_FRIENDS` | `4` | Сколько друзей может привести один человек |
| `ANNOUNCE_COOLDOWN` | `10m` | Сколько времени после объявления о наборе бот редактирует его вместо отправки нового |
| `PAYMENT_DRAFT_LOCK` | `1h` | Сколько оформление оплаты одним человеком блокирует его для других |
| `PAYMENT_MAX_CAME` | `30` | Максимум в ответе «сколько человек было» |
| `PAYMENT_MIN_TOTAL` | `1000` | Минимальная сумма за зал, ₽ |
| `PAYMENT_MAX_TOTAL` | `10000` | Максимальная сумма за зал, ₽ |
| `PAYMENT_ROUND_TO` | `10` | Шаг округления доли вверх, ₽ |

Системный cron не нужен: расписания выполняет сам бот, пока его процесс работает. При старте бот сразу делает то, что могло быть пропущено, пока он был выключен: очистку, создание игры, перерисовку сообщений и доски. Чтобы бот работал постоянно и перезапускался после сбоя, его запускают под `systemd`, в Docker с `restart: unless-stopped` или службой Windows.

`PLAYERS_LIMIT` и `MAX_FRIENDS` применяются сразу ко всем играм, в том числе уже созданным. Если уменьшить лимит, когда в игре записано больше, состав не урезается: показывается, например, «13/12 · состав собран», и новые записи не принимаются, пока не освободятся места.

## Запуск

Из корня проекта:

```powershell
go run .
```

Сборка в исполняемый файл:

```powershell
go build -o bin\volleyball_inline_bot.exe .
.\bin\volleyball_inline_bot.exe
```

При ошибке в конфигурации бот пишет её в лог и завершается с кодом 1. Остановка через Ctrl+C: бот дожидается завершения текущих задач планировщика и выходит.

Тесты:

```powershell
go test ./...
```

## Файл данных

Игры, списки игроков, отметки оплаты, реквизиты плательщиков и ID доски хранятся в одном JSON-файле, путь задаёт `STORE_PATH` (по умолчанию `data.json` в рабочей папке). Запись атомарная: бот пишет во временный `data.json.tmp` и заменяет им основной файл, поэтому сбой во время записи не портит данные.

Если файл потерян, бот начинает с пустого состояния: создаёт новую доску и закрепляет её, а сообщения старых игр остаются в чате, но кнопки в них перестают работать. Их нужно удалить вручную. При запуске в Docker файл нужно держать в volume, иначе он пропадает вместе с контейнером.
